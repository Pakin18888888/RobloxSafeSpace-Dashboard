# Roblox Safe Space — User flow / Workflow

## เปิดใช้งาน

เปิด `index.html` ด้วย Chrome, Edge หรือ Firefox ได้โดยตรง ไม่ต้องติดตั้งแพ็กเกจ ไม่ต้องเชื่อมอินเทอร์เน็ต และไม่มีการเรียก Backend

- ภาพรวม: ขอบเขตและแผนผัง 8 เมนูตามคลิป
- User flow: เส้นทางหลัก 8 ชุด พร้อมจุดตัดสินใจและกรณีผิดพลาด คลิกแต่ละขั้นเพื่อดูรายละเอียด
- Workflow: การส่งต่องานระหว่างเจ้าหน้าที่, Frontend, Backend และระบบเกม/ข้อมูล
- หน้าจอ & สิทธิ์: รายการหน้าจอ ฟิลด์ การกระทำ และสิทธิ์ที่เห็นในคลิป
- ทดลอง Login: ต้นแบบสถานะสำเร็จ, รหัสผ่านชั่วคราว, ข้อมูลไม่ถูกต้อง, ระบบขัดข้อง, ไม่มีสิทธิ์ และ session หมดอายุ ใช้ข้อมูลสมมติเท่านั้น
- หลักฐาน & ส่งต่อ: เวลาอ้างอิง รายชื่อ API ที่อ่านได้จากคลิป ข้อสงสัย และเกณฑ์ตรวจรับ

ปุ่ม “พิมพ์ / PDF” ใช้ระบบพิมพ์ของเบราว์เซอร์ เลือก Save as PDF ได้ โดยรวม flow และ workflow ทุกชุดไว้ในฉบับพิมพ์ ไม่ใช่เฉพาะตัวเลือกที่เปิดอยู่

## สถานะของงาน

นี่เป็นแบบออกแบบและต้นแบบประกอบการรีวิว ไม่ใช่ระบบ authentication หรือ Dashboard ที่เชื่อมต่อจริง ไม่มีการส่งข้อความเข้าหาเด็ก ไม่มีการแก้ไขข้อมูลจริง ไม่เก็บรหัสผ่าน/session ใน storage และไม่เผยแพร่ไฟล์ต้นฉบับขึ้นบริการภายนอก

แยกที่มาสามประเภทอย่างชัดเจน:

1. **เห็นในคลิป**: ยืนยันเฉพาะองค์ประกอบหน้าจอ ปุ่ม ข้อความ หรือชื่อ endpoint ที่อ่านได้ การมีปุ่มไม่ได้ยืนยันว่าการทำงานฝั่ง Server สำเร็จแล้ว
2. **เสนอ Frontend**: ลำดับหน้าจอ validation, loading/error, การยืนยันคำสั่ง และต้นแบบ Login ที่ออกแบบเพิ่ม
3. **ต้องยืนยัน**: API schema, error codes, session, permission keys, วิธีส่งข้อความถึงเกม และเงื่อนไขการเปลี่ยน/ลบข้อมูล

วิเคราะห์ภาพหน้าจอตามลำดับเวลาในคลิป ไม่ใช่บทถอดเสียง ไม่ได้เข้าถึง source code หรือทดสอบ Backend ของเพื่อน เอกสาร PDF ใช้เป็นบริบท ไม่ถือว่าเป็นฟีเจอร์ที่ Backend ทำเสร็จหรือเป็นคำสั่งเพิ่มขอบเขตงาน

ดู [หลักฐานและข้อจำกัด](docs/evidence.md), [User flow Mermaid ที่แก้ไขได้](docs/flows.mmd) และ [Workflow Mermaid](docs/workflow.mmd)

## ส่งต่อทีม Backend ก่อนเชื่อมจริง

ขอ API contract/OpenAPI และ payload ตัวอย่างที่ไม่มีข้อมูลจริง, session lifecycle/logout, permission keys, วิธีบังคับเปลี่ยนรหัสผ่าน, error mapping, และ delivery acknowledgement สำหรับการตอบผู้เล่น ยืนยันสิทธิ์การเห็น Alerts/บันทึกทีมทั้งใน Overview, Players และ export ด้วย

Frontend รับผิดชอบหน้าจอ การนำทาง การแสดงสถานะและการเรียก API ตาม contract ส่วน Backend ต้องตรวจสิทธิ์/ความถูกต้องทุก request จัดเก็บข้อมูลและ audit รวมถึงเชื่อมระบบเกม
